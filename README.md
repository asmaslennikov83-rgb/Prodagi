# WB Procurement Bot — расчёт закупок Wildberries

Telegram-бот рассчитывает закупку на основе заказов FBO + FBS, физического остатка на вашем складе и готовых комплектов/наборов.

## Как работает

1. Пользователь выбирает кабинет: кабинет 1, кабинет 2 или оба.
2. Выбирает период анализа продаж: 7 / 14 / 30 / 60 / 90 дней или свои даты. Быстрые периоды не включают сегодняшний день.
3. Выбирает целевой товарный запас: 1 / 2 / 3 / 4 недели (7 / 14 / 21 / 28 дней).
4. Выбирает коэффициент: 0,5 / 0,75 / 1 / 1,25 / 1,5.
5. Загружает файл остатков `.xls` или `.xlsx` с колонками `Код` и `Доступно`.
6. Загружает шаблон комплектов `.xls` или `.xlsx`.
7. Бот получает заказы WB, учитывает FBO и FBS, раскладывает проданные комплекты на компоненты, раскладывает остатки готовых комплектов в физический остаток компонентов и формирует Excel.

## Формула

- `Общий расход = FBO + FBS + расход компонентов через проданные комплекты`
- `Среднее в день = Общий расход / дней анализа`
- `Необходимо иметь = округление вверх(Среднее в день × целевой запас в днях × коэффициент)`
- `Физический остаток = отдельный остаток компонента + компоненты внутри готовых комплектов`
- `К закупке = max(0, Необходимо иметь − Физический остаток)`

Остатки FBO на складах Wildberries **не вычитаются**. Учитывается только физический остаток вашего склада/FBS, включая содержимое готовых комплектов.

## Шаблон комплектов

Поддерживается структура:

- `Название`
- `баркод комплекта`
- `баркод1`
- `баркод2`
- `баркод3` ...

Если один и тот же баркод указан несколько раз, это означает кратность. Например `баркод1 = 460...` и `баркод2 = 460...` означает 2 единицы этого компонента в комплекте.

## Итоговый Excel

### Лист `Закупка`

Баркод(ы), Артикул продавца, Бренд, Наименование, К закупке, На сколько хватит дней, Размер, Заказы FBO, Заказы FBS, Продажи комплектами, Общий расход, Среднее/день, Запас дней, Коэффициент, Необходимо иметь, Остаток FBO, Остаток FBS, Остаток учтён, Примечание.

### Лист `Комплекты`

Показывает заказы каждого комплекта, его остаток, состав и влияние на расход/остаток компонентов.

### Лист `Ошибки`

Неизвестные баркоды комплектов, компонентов, лишние баркоды из файла остатков и другие проблемы сопоставления. Ошибка в одной строке не останавливает весь отчёт.

## Доступ пользователей

В `.env`:

```env
ALLOWED_TELEGRAM_IDS=123456789,987654321
```

Пустой список запрещён — бот не запускается, чтобы случайно не открыть доступ всем.

## Настройка `.env`

Скопируйте `.env.example` в `.env` и заполните:

```env
TELEGRAM_BOT_TOKEN=...
WB_API_KEY_1=...
WB_API_KEY_2=...
CABINET_1_NAME=Кабинет 1
CABINET_2_NAME=Кабинет 2
ALLOWED_TELEGRAM_IDS=123456789
```

## Запуск Docker

```bash
docker compose up -d --build
```

Логи:

```bash
docker compose logs -f
```

## Запуск без Docker

```bash
pip install -r requirements.txt
python bot.py
```

## Важно

- Для старого формата `.xls` используется `xlrd`.
- Для `.xlsx` используется `openpyxl`.
- Сам баркод комплекта не попадает в лист закупки: закупаются его физические компоненты.
- Если товар отсутствует в файле остатков, его остаток считается равным 0 и в строке появляется примечание.
- Если товар не продавался, он остаётся в отчёте с закупкой 0.


## Выбор учитываемых остатков
После выбора коэффициента бот предлагает:
- Только FBO — текущие остатки на складах Wildberries через Analytics API; файл остатков FBS не нужен.
- Только FBS — остатки из загруженного файла склада.
- FBO + FBS — сумма текущих остатков WB и остатков из загруженного файла.

В обоих источниках остатки готовых комплектов разворачиваются в физические компоненты по шаблону комплектов.

В листе «Закупка» добавлена колонка «Бренд» перед «Наименование», а также отдельные колонки остатков FBO/FBS и фактически учтённого остатка.


## Обновление отчёта

На листе «Закупка» столбец «К закупке» расположен сразу после «Наименование». Следом добавлен столбец «На сколько хватит дней» = «Остаток учтён» / «Среднее/день». При нулевой средней скорости продаж значение равно 0.
